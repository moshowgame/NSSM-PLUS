# NSSM-PLUS 配置改造：单服务配置文件 + 配置目录集中管理（按已确认计划执行）

## 目标
把"一个 JSON 文件里放 services 数组、整体读写"的模型，改为 **每个服务一个独立配置文件**（`%ProgramData%\NSSM-Plus\configs\<serviceName>.json`），应用启动自动扫描目录加载全部配置。单个文件损坏/被删不影响其他服务。旧的多服务合并 JSON 保留为"导入/导出"格式，平滑迁移。前端维持现有 Vue 3 技术栈不变。

## 一、后端 `internal/config/config.go`
新增：`Dir()`、`FilePath(name)`、`ServiceFile{FilePath, Config, Error}`、`LoadDir(dir)`（扫描 *.json，单文件出错记入 Error 不影响其他文件，serviceName 重复/文件名不匹配标记冲突）、`SaveServiceTo(dir, cfg)`、`SaveService(cfg)`、`DeleteService(name)`。规范化逻辑（appPath 拆分、密码解密）抽成 `normalizeConfig` 复用。保留 `SaveToFile`/`LoadFromFile` 作旧格式导入导出。

## 二、绑定层 `app.go`
新增绑定 `GetConfigDir`、`LoadConfigDir`、`SaveServiceConfig(oldName, cfg)`（改名时删旧文件）、`DeleteServiceConfig(name)`。`InstallService`/`ModifyService` 成功后自动落盘配置文件（失败仅记日志，不影响安装结果）。

## 三、CLI `internal/cli/cli.go`
`import <file|dir>`：支持文件或目录，写入 configs 目录单文件并安装；`export` 新增 `--dir <path>` 拆分为每服务一个文件。更新 usage 帮助文本。

## 四、前端（Vue 3 不变）
- App.vue：`configFilePath`+localStorage 模型 → 固定 `configDir`（启动时 GetConfigDir）；`LoadConfigDir` 替代单文件加载；loadConfig→导入（拆分写入目录）、saveConfig→导出全部聚合 JSON、saveService→单文件保存（支持改名删旧文件）、deleteConfig→删配置文件；头部显示配置目录；解析失败文件在头部显示 ⚠N 警告。
- ActionBar.vue：按钮改为 Import Config / Export Config，Save Service 不再依赖 configFilePath。
- i18n en.json/zh.json 同步更新文案。

## 五、示例与文档
configs/example.json 保留为旧格式导入示例，新增单服务示例；更新 README.md、CLAUDE.md。

## 六、测试
新增 internal/config/config_test.go：SaveService/LoadDir 往返、损坏文件容错、重复/不匹配冲突、改名删除旧文件、非法服务名拒绝。
